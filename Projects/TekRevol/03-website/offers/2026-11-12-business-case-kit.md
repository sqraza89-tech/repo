## 1. One-page business case template

Approvers read one page. Keep each section to two or three lines.

| Section | What to write |
|---|---|
| **The problem** | What isn't working, in business terms. "Orders are entered three times" beats "the system is outdated" |
| **What it costs today** | Hours per week, error rate, delays, lost sales, risk. Use the ROI worksheet (section 3) |
| **The cost of waiting** | What happens in 12 months if nothing changes: more headcount, more errors, a growth target missed |
| **What we propose** | The solution in one sentence, plus the first stage |
| **Options we considered** | Doing nothing, an off-the-shelf tool, connecting what we have, building custom. One line on why each was or wasn't chosen |
| **Cost and timeline** | Planning range and time to first working release. Show the phases, so approval can be staged |
| **Expected return** | Annual savings or gains, and the payback period |
| **Risks and how we'll manage them** | Two or three, each with a response |
| **The ask** | What you need approved now. Often just discovery, not the whole project |

**Tip:** ask for approval of the first stage, not the full budget. A paid discovery with a fixed quote at the end is an easier yes, and it gives your approvers real numbers.

**What moves the price**
- **Integrations:** each system you connect adds work, more if it has no documented API
- **User roles and permissions:** three roles is simple; fifteen is not
- **Platforms:** web, iOS and Android each add design, build and testing
- **Compliance:** HIPAA, PCI DSS or SOC 2 controls add security work and documentation
- **Data migration:** moving years of history from old systems
- **Certainty:** a clear, stable scope costs less than one that changes every sprint

## 3. ROI worksheet

Fill in your own numbers. Conservative inputs make a stronger case than optimistic ones.

| Line | Input | Your number |
|---|---|---|
| A | Hours per week spent on the manual process (all people) | |
| B | Fully loaded hourly cost (salary + benefits + overhead) | |
| C | Share of those hours the software removes (be conservative: 50 to 70%) | |
| D | **Annual time savings** = A × B × C × 48 weeks | |
| E | Annual cost of errors today (rework, refunds, write-offs) | |
| F | Share of errors the software prevents | |
| G | **Annual error savings** = E × F | |
| H | Licenses or tools you can retire, per year | |
| I | Added revenue (faster quotes, more capacity), if you can defend it | |
| J | **Total annual benefit** = D + G + H + I | |
| K | Project cost (planning range, upper end) | |
| L | Annual support and hosting | |
| M | **Payback period in months** = K ÷ (J − L) × 12 | |

**Worked example (illustrative numbers, not a client result)**

A distributor with 120 employees re-keys orders between its order system and accounting.

| Line | Value |
|---|---|
| A. Hours per week | 30 |
| B. Hourly cost | $45 |
| C. Share removed | 70% |
| D. Annual time savings | 30 × 45 × 0.7 × 48 = **$45,360** |
| E. Annual cost of errors | $30,000 |
| F. Share prevented | 60% |
| G. Annual error savings | **$18,000** |
| H. Retired tools | $4,000 |
| I. Added revenue | $0 (left out to stay conservative) |
| J. Total annual benefit | **$67,360** |
| K. Project cost | $80,000 |
| L. Support and hosting | $12,000 |
| M. Payback | 80,000 ÷ 55,360 × 12 = **about 17 months** |

## 4. Build, buy or connect: a quick test

| If this is true | Consider |
|---|---|
| A standard tool covers 80% or more of what you need, and the rest can change | **Buy** |
| Your tools are fine, but data is typed into several of them | **Connect** |
| The workflow is how you win business, and no tool fits it | **Build** |
| Your core system works but is slow, costly or hard to change | **Modernize in stages** |
| You're paying for workarounds: extra headcount, spreadsheets, manual reports | **Build or connect** |

Many companies end up with a mix: off-the-shelf tools for standard work, custom software for what makes them different, and integration in between.

## 5. Vendor evaluation checklist

Ask every vendor the same questions, including us.

**Delivery**
- Will we see working software every two weeks, or only status reports?
- Who is our single point of contact, and how senior are they?
- Who signs off that a release is ready for production, and against what checklist?
- Can we speak to two clients with a similar project?

**Cost**
- Do you publish price ranges? Do you give a fixed quote, and when?
- What happens if scope changes mid-project?
- What does support cost after launch?

**Ownership**
- Do we own the source code and IP from the first commit?
- Will you sign an NDA before discovery?
- If we part ways, what do we get: code, documentation, credentials?

**Security**
- Which certifications do you hold, and which standards do you have experience with?
- How do you handle our data and access to our systems?
- How are security checks built into your development process?
